# 分发前的文章短链接

当前实现支持按成稿平台和账号保存已有短链或公众号直链，在正文末尾预览并冻结。落地文章由操作者核对。下列自动逐跳校验、按段落放置和发布端验收属于后续设计。

## 运营配置

运营者设置一条固定的目标微信公众号文章 URL、读者可见文案（如「延伸阅读」）和适用平台/账号/内容形态，可按规则指定插在正文末尾或指定段落之后。目标可以和本次分发素材的原文不同。source_url 永久保存文章来源；destination_url 专门保存运营者提供的跳转目标。来源说明和延伸阅读分别展示。

可先使用运营者提供的现成短链接；后续如需自动生成，再接入自有域名或明确选定的服务。未配置时不发起外部建链请求。一个固定目的地可跨稿复用同一短链，无需为每条任务重复创建。变更目的地生成新版本并对待发内容重新预览，已发表稿件保留其原目标和审计记录。

## 插入点与渠道规则

1. 版本生成后、最终质检前，在一个带标识的结构化段落中插入链接。HTML 节点、Markdown 链接或纯文本 URL 依平台实际渲染能力选择。把文案、短链接、预期目标和 placement 一并写入冻结版本。重生成、重试或改期时同一版本最多插入一次。
2. 配置按「平台 × 账号 × 内容形态」记录是否允许外链、是否允许短链域名、有效期和依据。明确允许且通过校验才插入；仅允许微信原始 URL 时可按运营者预设使用直链。规则未知、禁止或审核结果不确定时，按配置省略推广段或转人工。不用短链绕过外链过滤。
3. 校验用户提供的目的地确属 HTTPS 微信公众文章 URL。已有短链在独立受控检查器中逐跳检查域名、重定向上限、HTTPS 和最终文章身份，限制内网/本机地址，未经确认的落地页、目的地漂移或失效需重新审批。验证页或登录页只标“待人工验证”。HTTP 200 不能证明读者能到达目标文章。
4. 预览在一处并排显示读者文案、实际短链、最终公众号文章、插入位置和该渠道的决定。插入后重新检查字数、格式和外链规则。正式启用时，由获准账号验证读者端可点击且能到达指定文章。发布任务记录 link_version、插入/省略原因和最近验证时间。
5. 模拟环境使用本地假重定向响应；不创建公网链接，不采集读者数据。点击分析非本功能的必要条件。

## 验收

| 情形 | 预期 |
|---|---|
| 来源文章 A，统一引导文章 B | 来源仍指 A；读者点击延伸阅读到 B |
| 允许短链的平台、仅允许直链的平台、不可插入的平台 | 分别得到可点短链、获准直链、省略或待审，三份版本互不影响 |
| 100 篇文章共用 B；并发排期、重试或重新生成 | 同一固定目标按规则复用，最终每份正文至多一个指定推广段 |
| 链接失效、最终目的地变为 C、平台将链接变成纯文本 | 展示原因并按渠道策略处理；不能标为可跳转 |
| 目标在审核后、发布前改变 | 原版本可追踪，待发布版本重新校验；已发布记录可还原当时配置 |
